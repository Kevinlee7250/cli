## 3. 손으로 돌리는 방법

### 방법 A — GitHub 웹 화면 (권장)

1. 브라우저에서 `github.com/Kevinlee7250/cli` 접속
2. 상단 **Actions** 탭 클릭
3. 왼쪽 목록에서 돌릴 워크플로 이름 클릭
4. 오른쪽 **Run workflow** 버튼 클릭
5. 입력값을 채우고 초록색 **Run workflow** 클릭
6. 잠시 뒤 목록 맨 위에 실행이 뜹니다. 클릭하면 진행 상황이 보입니다

### 방법 B — 명령어 (`gh` 설치돼 있을 때)

```bash
cd C:\Users\chris\cli-fix

# 감사만 (아무것도 안 바꿈)
gh workflow run fix-experience-claims.yml --ref latest \
  -f step=audit -f dry_run=true

# 결과 보기
gh run list --workflow=fix-experience-claims.yml --limit 3
gh run view <실행번호> --log
```

## 4. 안전 규칙 4가지

이 네 가지만 지키면 되돌릴 수 없는 사고는 나지 않습니다.

### ① 발행된 글을 고치기 전에는 반드시 백업

**📦 공개 글 원본 백업**을 먼저 돌리세요.
`blog-automation/backups/live_posts_<날짜>.json`에 본문 전체가 저장됩니다.

되돌릴 때:
```bash
cd blog-automation
python backup_live_posts.py --restore backups/live_posts_<날짜>.json --dry-run
python backup_live_posts.py --restore backups/live_posts_<날짜>.json
```

### ② 첫 실행은 무조건 `dry_run`

`titles`·`bodies`·`enrich`·`curate-apply`는 **실제 발행 글을 바꿉니다.**
먼저 `dry_run=✔`로 돌려서 무엇이 바뀔지 로그로 확인한 뒤,
같은 입력값에 `dry_run`만 끄고 다시 돌리세요.

### ③ 나눠서 돌리기

`limit`을 10 안팎으로 두고 여러 번 돌리세요.
한 번에 전부 돌리면 중간에 끊겼을 때 어디까지 됐는지 알기 어렵습니다.
(대부분의 도구는 이미 처리한 글을 건너뛰므로, 다시 돌려도 안전합니다)

### ④ 덮어쓰기는 일부러 켤 때만

필수 페이지 생성은 **없는 것만 만드는 것이 기본값**입니다.
손으로 고쳐 둔 개인정보처리방침을 자동 생성본으로 덮으면 되돌릴 수 없습니다.
정말 새로 쓰고 싶을 때만 `python page_creator.py --overwrite`.

## 5. 이 시스템이 절대 하지 않는 것

거절 사유였던 "지어내기"를 막기 위해 일부러 넣은 제약입니다.
**작동이 안 되는 게 아니라, 안 하도록 만들어 둔 것입니다.**

| 상황 | 동작 |
|---|---|
| 참고자료를 만들 뉴스 자료를 못 찾음 | 주제의 **공식 기관 대표 페이지**로 대체 (`topic_sources.json`, 전부 접속 확인된 실제 주소). 주제도 안 맞으면 그 글은 건너뜀 |
| Search Console 노출이 0 | 수익 추정치를 만들지 않고 `measured:false`로 이유를 남김 |
| FAQ 답변에 본문에 없는 수치가 들어감 | 그 항목만 버림 |
| FAQ 답변이 경험을 주장함 | 그 항목만 버림 |
| 드라마 글 자료팩에 시청률이 없음 | 시청률 H2를 통째로 생략 |
| 제목 교정 중 주제어가 훼손됨 | 교정을 취소하고 안전한 치환으로 대체 |

로그에 위 문구가 보이면 **정상입니다.** 고칠 것이 아니라,
사람이 실제 자료를 찾아 넣어야 하는 글이라는 뜻입니다.

## 6. 문제가 생겼을 때 확인 순서

```bash
cd C:\Users\chris\cli-fix

# 1. 최근 실행 결과 — failure가 있는지
gh run list --limit 15

# 2. 실패한 실행의 로그
gh run view <실행번호> --log-failed

# 3. 발행이 안 됐는지 확인
gh run list --workflow=blog-run.yml --limit 5
```

자주 나오는 상황:

| 증상 | 원인 | 조치 |
|---|---|---|
| `invalid_grant` | Google 토큰 만료 | MANUAL.md 8장 |
| `Connection reset by peer` | 일시적 네트워크 | 그냥 다시 돌리기 |
| 발행 0건인데 성공 | 오늘 몫을 이미 발행함 | 정상 |
| 커밋 충돌로 실패 | 두 워크플로가 동시에 푸시 | 다시 돌리기 |
