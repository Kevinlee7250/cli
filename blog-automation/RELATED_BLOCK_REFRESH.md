# 관련 포스트 블록 교체 — 인수인계

> 이 문서는 **아직 하지 않은 작업**의 계획서입니다. 백업까지만 끝났습니다.
> 새 세션은 이 문서만 읽고 이어받을 수 있어야 합니다.

## 1. 무엇을 고치려는가

공개 글 81편에 경험 주장 표현이 39건 남아 있습니다. 위치 분포:

| 위치 | 건수 | 비중 |
|---|---:|---:|
| **관련 포스트 / 해시태그 블록** | **23** | 59% |
| 실제 본문 문장 | 16 | 41% |

관련 포스트 블록은 *다른 글의 제목과 요약을 인용한 카드*입니다. 실제 예:

> 📖 관련 포스트 — 모로코 여행 혼자 가도 괜찮을까, 12일 솔직 후기 정리 /
> **모로코를 혼자 12일 다녀온 경험과** 국제 안전 지수 자료로…

인용된 원글은 2026-09-13 재편 때 임시저장으로 내려갔습니다. **인용문만 살아있는 페이지에 남았습니다.** AdSense 심사관이 읽는 것이 이 텍스트입니다.

## 2. 왜 지금까지 자동으로 안 고쳐졌나

- `related_posts.build_related_section()` 은 **글을 새로 발행할 때만** 호출됩니다.
  이미 발행된 글의 블록을 다시 쓰는 코드는 없습니다.
- `fix_experience_claims.py` 는 `<p>` 단위로 문장을 교체합니다. 관련 포스트는
  산문이 아니라 카드 마크업이라 교체가 걸리지 않고, 매번 "교체된 문단 없음"으로
  빠집니다. 배치 3회를 돌려 21편을 고쳤지만 이 23건은 한 번도 안 걸렸습니다.

## 4. 남은 작업 계획

### 4-1. 원칙

**되돌릴 수 있는 상태를 유지한 채로만 진행합니다.** Blogger에는 본문 버전
기록이 없습니다. `blog-automation/backups/` 의 백업이 유일한 복구 수단입니다.

### 4-2. 순서

1. **최신 백업 확인** — `backups/` 에 오늘자 파일이 있고 `count`가 공개 글 수와
   같은지. 다르면 백업부터 다시.
2. **블록 경계 파악** — 백업 JSON에서 관련 포스트 블록의 실제 HTML을 눈으로
   확인. 카드 마크업이 글마다 같은지, 버전이 섞여 있는지. **여기서 시간을
   써야 합니다.** 정규식은 그다음입니다.
3. **추출기 작성 + 테스트** — 블록을 찾아내는 함수만 먼저. 백업에 든 81편
   전부에 돌려 "찾음/못 찾음/여러 개"를 세어 봅니다. 못 찾는 글이 있으면
   건드리지 않습니다.
4. **교체기 작성** — 블록을 `build_related_section()` 의 새 결과로 치환.
   후보는 `live_posts.json` 기준이므로 내려간 글은 자동으로 빠집니다.
5. **dry-run diff 검토** — 교체 전후를 사람이 읽습니다. 본문 길이 비율,
   블록 외 영역이 변했는지 반드시 확인.
6. **소량 배치** — 3편 → 확인 → 10편 → 확인 → 나머지.
7. **감사 재실행** — 39건 중 23건이 빠졌는지 확인.

### 4-3. 반드시 넣을 가드

- **블록 밖은 한 글자도 바뀌지 않을 것.** 교체 전후에서 블록을 제거한
  나머지 문자열이 완전히 동일한지 비교.
- **블록을 못 찾거나 2개 이상 찾으면 건너뛰기.** 추측해서 자르지 않습니다.
- **본문 길이 비율 하한.** `fix_experience_claims.MIN_LENGTH_RATIO` 와 같은
  방식. 크게 줄면 thin content 판정을 새로 만듭니다.
- **`--limit` 기본값을 작게.** 전체 실행이 기본이면 안 됩니다.

## 5. 사고가 났을 때

```bash
cd blog-automation

# 무엇이 복원되는지 먼저 본다
python backup_live_posts.py --restore backups/live_posts_<stamp>.json --dry-run

# 글 하나만 되돌리기
python backup_live_posts.py --restore backups/live_posts_<stamp>.json \
  --url https://www.hoguwhat.com/2026/09/blog-post_04.html

# 전체 되돌리기 (제목·본문 모두)
python backup_live_posts.py --restore backups/live_posts_<stamp>.json
```

`restore` 는 백업 파일을 먼저 검사합니다. 빈 본문이 하나라도 섞여 있으면
아무것도 하지 않고 멈춥니다 — 그 백업으로 복원하면 글이 지워지기 때문입니다.

## 7. 하지 않기로 한 것

- **medium 27편을 추가로 내리는 것.** 공개 글이 81 → 54편이 됩니다. AdSense는
  콘텐츠 양도 봅니다. 인용문을 고치는 쪽이 낫습니다.
- **워크플로 버튼으로 전체 복원.** 한 번 누르면 81편이 되돌아갑니다. 복원은
  사람이 판단해 로컬에서 돌립니다.
